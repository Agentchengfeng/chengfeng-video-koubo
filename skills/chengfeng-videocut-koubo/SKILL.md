# 剪口播

从一条真实录音到剪好的人声，七步一线。原素材只读不改，所有东西都写在**工作目录**里（默认放在录音旁边，叫 `<录音名>-剪口播/`）。脚本都在本 skill 的 `scripts/` 里，下面写 `S=<本 skill 目录>/scripts`。

```text
1 转录   录音 → 逐字稿（每个字带时间）                          转录.py      付费
2 修字   听错的专名改对，出修字表                               修字.py
3 删词   先通览整段找重录，再逐字五轮找口误                      AI 读稿判断
4 汇总   写删词.json → 两张表 + 删后全文 → AI 自己从头读一遍      删词.py
5 剪     真的剪，压停顿，刀口挪到安静处                          剪.py
6 核对   豆包再听一遍剪好的人声，逐字对出漏删和切坏的字          核对.py      付费
7 交付   审核页给用户听；用户说哪里不对就回第 4 步重来            审核页.py
8 复盘   对比 AI 第一版和终版，口味和专名记下来
```

**每一步的完成判据是它的产出文件**：没出文件，不算做完。**用户只在两处说话**：开头说清要剪哪条、要不要先看审核页；最后听审核页、说哪里要改。其余不打断。

## 0. 准备

- 要有 `python3`（3.8 以上，只用标准库）和 `ffmpeg`、`ffprobe`。缺了就告诉用户怎么装（macOS：`brew install ffmpeg`），不替用户装。
- 豆包识别 key：环境变量 `VOLCENGINE_API_KEY`，或者 `~/.chengfeng-videocut-koubo/config.json` 里的 `volc_api_key`（要指定资源时加 `volc_resource_id`，不写就依次试 `volc.seedasr.auc`、`volc.bigasr.auc`）。没有 key 就停下，告诉用户去火山引擎开通“录音文件识别”。key 不打印、不写进别的文件。
- 识别按时长收费，第 1 步、第 6 步各识别一次（第 6 步复核还会对可疑刀口各识别两小段）。开工前跟用户说一声。
- 用户的口味和专名词典放在 `~/.chengfeng-videocut-koubo/偏好.md`、`~/.chengfeng-videocut-koubo/词典.md`，没有就是新用户。

## 1. 转录

```sh
python3 $S/转录.py <录音或视频> <工作目录> --热词 'Codex,Claude'
```

热词写这条录音里会出现的专名（用户说过的、稿子里有的）。产出 `逐字.json`（以后各步都读它）和 `逐字稿.txt`（一句一行：句号、字号范围、开始时间、原话；停顿 ≥0.8 秒和拖长的字另起一行标出）。

- 已经转过就别再转：脚本发现 `逐字.json` 已有会停下。
- 查询超时会打印任务号并退出（码 2）：加 `--接着查 <任务号>` 再跑，**不重新提交**，重新提交会再扣一次钱。

## 2. 修字：先把字改对

先读 [专名词典](references/专名词典.md) 和用户的 `~/.chengfeng-videocut-koubo/词典.md`（用户的优先），对着 `逐字稿.txt` 找听错的专名，写 `修字.json`，再跑：

```sh
python3 $S/修字.py <工作目录> <工作目录>/修字.json
```

- `修字.json` 每次写全部要改的：脚本每次从转录原样开始改。
- 只改写法，不改意思；说话人真说错又重说，归第 3 步删词，不归这里。
- 读的时候连着上下文看意思，不只看专名：前后都在讲 Claude 的上下文窗口，识别写成“上下问窗口”，那就是“上下文”听错。
- 稿里一次正确写法都没出现过、上下文也确认不了的，不改，记下来报告。不猜。
- 中文口语照原话（说“叉”就是“叉”），词典只管同一个专名的多种写法和明显听错。
- 修字一定在删词之前做完：稿子是错的，后面判断就得一路绕开错名字。

## 3. 删词：先通览整段，再逐字五轮

先读 [删词规则](references/删词规则.md)（原则、判例、风险）和用户的 `~/.chengfeng-videocut-koubo/偏好.md`。教材优先级：**用户偏好 > 用户判例 > 通用判例**。判断只看 `逐字稿.txt` 的顺序，从第一句读到最后一句，不跳读。

**第一层：通览所有句子。** 先读完整篇，再找相隔很远的重录：同一个意思说了几遍、哪遍完整、几遍之间差在哪、保哪遍、删哪遍。不能只比相邻句；关键词不同不等于不是重录，也不等于是重录，看上下文。顺手标**换要点**：下一句开始讲新的要点（“第一/第二”“另外”、转到总结），记下这一句的句号。

**第二层：剩下的逐字流扫五轮，每轮只带一个判据：**

```text
第 1 轮  重复          句间重复、句内重复（最客观：两遍一样）
第 2 轮  残句与改口     说一半断掉、换个说法重说
第 3 轮  口误重说       说错的数字、专名、词，后面又说对了
第 4 轮  英文卡壳       词头、字母、音节重复
第 5 轮  口头禅与语气词  最主观，按用户偏好的密度来
```

每轮找到一处记一行（句号、删哪几个字、类型、风险），不替别的轮下结论；冲突留到汇总解决。整篇很长时，读完、通览完以后可以把五轮分给几个子 Agent 并行扫，但子 Agent 只交候选行，不写文件、不跑剪；由你去重、合并成一份。

规矩：

- **删前保后**：前一遍不完整或说错的删，后一遍完整说对的留。
- 删除只有“删 / 不删”两态，没有“建议删、等用户点头”。拿不准就不删。
- 整句、长段、同开头后半分叉、专名或数字改口一律高风险：回到稿里把前后念一遍，确认删的是靠前那一版、删完读得通，确认不了就不删。
- 删一遍重说时，删到前后最近的停顿为止，别在连着说话的中间下刀。
- 停顿不用你管：剪的时候按标点自动压，你只标换要点。

## 4. 汇总：写删词.json，出两张表

把第一层的重复组和五轮的行合成一份 `删词.json`（格式见 `删词.py` 开头的说明：`删`、`重复句子`、`换要点` 三项），然后：

```sh
python3 $S/删词.py <工作目录> <工作目录>/删词.json
```

产出 `两张表.md`（删词汇总表：每条删了什么、剩下读作什么、风险、依据；重复句子表：说了几遍、保哪遍、删哪几遍）和 `删后全文.txt`。

**然后自读**：把 `删后全文.txt` 从头读一遍，读不通的条目撤掉，改 `删词.json` 重跑这一步。这是你自己再看一遍，不是拿去问用户。

`删词.json` 每次都写**这一轮的全部结论**，不是只写新找到的：脚本按整份文件剪，只写新的，上一轮的删词就没了。

## 5. 剪

```sh
python3 $S/剪.py <工作目录>
```

产出 `剪后.wav`（源是视频时另有 `剪后.mp4`）、`剪辑表.json`（每段从原素材哪到哪、每个刀口在剪后第几秒）、`接缝待听.md`。

- 停顿按前一个字后面的标点分档，只缩不拉长：句中 0.13 秒、逗号 0.2 秒、句末 0.3 秒、换要点 0.5 秒。用户不要压停顿就加 `--不压停顿`。
- 刀口由脚本按响度挑附近最安静的 10 毫秒，接缝两边做 5 毫秒淡入淡出。你不猜毫秒数，也不手改剪辑表。
- 刀只能落在连着说话的地方、或刀口附近不够安静的，进 `接缝待听.md`。列表不空时不说“剪好了”，说“N 处接缝待人耳确认”。

## 6. 剪后核对：到 0 条才算剪好

```sh
python3 $S/核对.py <工作目录> --热词 '<同第 1 步>'
```

豆包把 `剪后.wav` 再听一遍，跟“应该剩下的字”逐字对。退出码 0 = 没有要回去听的；1 = 有 ▲ 条：

- **重复**（如“它自己它自己”）= 该删的一遍没删干净：回第 3 步补进删词（删前保后），重跑 4–6。
- **刀口上多出来 / 变了** = 刀落在重念那遍的尾音上，或切进了留下的字：看 `剪辑表.json` 那个刀口删掉了什么，多半是删词的头尾差一两个字，改 `删词.json` 重跑 4–6。不手写毫秒。
- **少了** = 留下的字被切掉：查是不是误删了相邻的字，改了重跑。
- `·` 条是两次识别写法不同（Codec/Codex）或同音字，不改。

核对是机器识别比对，不是人耳听过。报告写“剪后核对：0 条 / N 条要回去听”，不写成“听过没问题”。

## 7. 交付：审核页

```sh
python3 $S/审核页.py <工作目录>
```

打开 `审核页.html`：上面是剪后和原声两个播放器，下面两张表、接缝待听、核对结果，点哪条就跳到哪儿听。用户说哪条要恢复、哪里还要删，改 `删词.json`，从第 4 步重跑到第 7 步。用户说不用看审核页，直接交 `剪后.wav` / `剪后.mp4`。

**报告给用户四件事**：删了多少处、少了多少秒（原长 → 剪后长）；剪后核对几条；接缝待听几处；没人听过的部分写“没人耳听过”。

## 8. 复盘：用户改过的不许扔

用户听完定稿后，拿 AI 第一版 `删词.json`（改之前先存一份 `删词-第1版.json`）和终版比：

- **用户恢复的**（第一版删了、终版没删）= AI 删错了：错在哪一类？
- **用户补删的**（终版删了、第一版没删）= AI 漏了：属于哪一类，为什么没看出来？
- 核对查出的漏删也算 AI 漏了。

记下来：口味差异追加进 `~/.chengfeng-videocut-koubo/偏好.md`（没有就建）；专名错误追加进 `~/.chengfeng-videocut-koubo/词典.md`（两列表格：正确写法 | 听成了什么，追加前查重）；零差异也记一行“全盘采纳”。同一类规则空白出现第三次，告诉用户，建议写进本 skill 的删词规则。

## 出错时

- 识别超时：用 `--接着查`，不重新提交。
- 原素材挪了位置：`剪.py` 会停下，问用户新位置，改 `逐字.json` 里的 `源`。
- 任何时候都不把“删词结果写好了”说成“剪好了”：剪好了是 `剪.py` 跑完、核对 0 条。

规矩的来历见 [事故簿](references/事故簿.md)。
